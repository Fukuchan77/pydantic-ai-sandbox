## Success Pattern OR Mistake Record

### Pattern

- **Problem**: 別 repository の新 Python 対応を検証する際、対象 worktree を直接編集したり、最初の gate failure で停止したり、diagnostic の成功を required verdict と混同すると、再現不能・破壊的・false-green な証拠になる。
- **Solution**: immutable commit を `git archive` で full scratch 化し、許可された migration だけを適用する。required phases と non-gating diagnostics を別 schema で記録し、exit code は最初の required failure を保持したまま diagnostics を最後まで走らせる。artifact の要点は dated ledger へ転記する。
- **Implementation**: `.sdd/patterns/immutable-upstream-verification-ledger.md` 参照。source/output 境界、symlink、mise trust、interrupt cleanup、required schema、warning origin を hermetic contract tests で固定する。
- **Benefits**: upstream の失敗を「検証基盤の失敗」と誤認せず、同時に diagnostic green を採用可の証拠へ昇格させない。commit、migration、commands、versions、warnings、retry condition を監査可能に残せる。
- **Evidence**: `scripts/verify-hub-python.sh`、`scripts/summarize_hub_verification.py`、`tests/unit/test_hub_verification_runner.py` 29 passed、ledger §6、root coverage 98.51%。

## Learnings → Rules Mapping

| Learning | Candidate rule / steering update |
|----------|----------------------------------|
| upstream verification は「required verdict」と「診断情報」を別物として扱う | 外部 repository 検証 runner は required phase の exact schema と first-failure exit preservation を必須にする |
| immutable と主張するなら commit SHA だけでなく full archive・source 非変更・migration diff を検証する | source sentinel、scratch-only migration、output outside source、symlink rejection を標準 contract test checklist に追加 |
| artifact path は一時物であり、意思決定の正本にできない | dated evidence ledger へ commit / commands / versions / verdict / retry condition を転記し、artifact path は参考扱いにする |
| dependency compatibility は metadata range だけでは保証できない | solver floor/ceiling test に加え、実際の provider construction と request path を executable contract にする |
| fixture が upstream repository shape を推測すると hermetic test 自体が誤る | 初回 immutable run 前に対象 commit の pin / task / lane path を確認し、fixture が実形状を表すことを PROVE する |
| beta lane の成功は upstream gate の成功と同義ではない | 「runner implementation readiness」と「upstream adoption readiness」を Check / Act で別判定にする |

## Process Improvements

- **初回実行前の repository-shape preflight**: target commit の Python pin、mise task 名、API lane path、required sentinel を列挙し、fake repository fixture と比較する。今回の root `.python-version` 仮定のような誤差を本実行前に潰す。
- **dependency floor は構築だけでなく request まで検証**: provider object が作れるだけでは transport mismatch を取り逃がす。method、URL、body、timeout、response round-trip まで mock transport で固定する。
- **required schema を closed set にする**: summarizer は stage 名の部分一致を避け、`uv-lock` / `uv-sync` / `api-check` の exact set を要求する。欠落・重複・未知 stage は verdict unavailable として loud-fail させる。
- **失敗後 diagnostics の継続をテストする**: required phase が赤でも lint/test/audit の全ログを回収する契約を持つ。ただし diagnostic divergence は required verdict を上書きしない。
- **VDD finding を一次情報で収束する**: dependency version の存在、metadata、transport behavior は PyPI metadata、installed source、isolated env、mutation/PROVE で再確認し、ドキュメント上の推測を残さない。
